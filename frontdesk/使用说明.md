# 卡秀商务酒店 · 前台系统

## 打开方式

回到项目文件夹，双击 `启动前台.cmd`（或 `start-frontdesk.cmd`），浏览器会自动打开。保留启动时的小窗口运行；浏览器可以关闭再打开。电脑重启后，再双击启动即可。

本机地址：http://127.0.0.1:8765 。只供这一台前台电脑使用，不需要互联网，不向外网发布。当前电脑已安装 Python；如果换电脑，需要安装 Python 3.10 或以上，并完整复制 `frontdesk` 文件夹及启动文件。

不要直接双击 `frontdesk/web/index.html`，它需要通过上面的本机服务访问。

## 第一次使用

1. 在“设置与备份”填写四种房型的参考房价，可设置默认为线下保留几间房；新订单可改为实际成交价。
2. 把现在在住的客人，以及携程、美团所有已经确认的未来订单，逐笔录入并分配具体房号。
3. 对照两个平台实际订单，确认没有漏单，然后在“平台调房”逐日核对平台剩余可售房量。

系统初始是空账本，显示 13 间空房，不代表酒店实际还有 13 间可售。录入现有订单后再使用建议库存。

## 每天怎么操作

- 来了一笔订单：点房号 → 填入住日期、离店日期、客源和总房费 → 保存。默认只显示这四项；姓名、电话、备注等在“更多信息”中选填。不填姓名会显示“未留姓名”。
- 续住三四晚：点原订单 → 修改离店日期 → 核对整个住宿期间总房费 → 保存。系统逐晚查冲突，如后面已经有预订会阻止保存；可调整到其他可用房间，但这会修改整笔订单的房号，跨房分段住宿请分两笔登记。
- 到店：在“更多信息”中将预订状态改为“在住”。退房：改成“已退房”；提前离店请核对实际离店日期和总价。已收超过新总价时，先登记退款。新增订单会根据入住日期自动选择在住或预订状态。
- 房间维修：新增记录，在“更多信息”中将状态选为“停用”，填写备注及起止日期。停用同样扣房量。停用结束可缩短日期，取消停用记录会释放整段日期。
- 收钱或退款：打开订单 → 收 / 退款 → 填金额与方式。这里是记账，不会真的向客人扣款或退款。
- 交班：核对当天流水、到期在住和平台订单 → 导出完整备份。

入住日期占房，离店日期不占当晚。例如 9 月 13 日入住、17 日离店，占用 13、14、15、16 日四晚。已到离店日但仍标为“在住”的房间会保护今天的库存，直到前台确认退房或续住。同日入住又离店的订单仍按一晚占用处理。

## 平台房量规则

**本系统没有接入携程或美团，不会自动拉取订单、改库存或关闭售卖。** 前台必须及时登记平台订单，并手工完成调房。人工操作延迟期间仍可能超售。

每一天、每一种房型：`携程剩余可售 + 美团剩余可售 + 线下留房 = 本机剩余房量`。

默认扣除线下留房后均分给携程和美团；奇数多分一间给携程。可逐日手动分配。只有一间高级观景房时，默认只给携程一间、美团零间，也可改为给美团。不要在两个互不连接的平台各放一间。

调整顺序：先在两个平台减少或关房，再增加房量；确保所有套餐 / 售卖产品合计不会重复放量，再点本系统的“核对并确认”。核对记录只代表前台确认过当时的数字，不是实时连接状态。

连续日期的建议数量相同时会自动合并；例如“13 日至 16 日”表示这四晚每一晚都设置为显示的可售间数，不是四晚合计。一次确认会逐日保存核对记录。

新增、修改、取消订单或停用房间后，建议房量会重新计算；只要线上建议数与上次核对数不同就重新提示。首页覆盖未来 14 天，调房页可查看 14 / 30 / 90 天，并可选择更远日期。远期订单需要查看相应入住日期。

手动分配以线下留房优先，再按携程、美团顺序缩减。新增空房默认留在线下；如果要重新分给平台，手动修改或点击“恢复默认均分”。

## 金额说明

设置中的参考房价用于自动填总价，登记窗口只需填一项总房费。改日期时会按原参考价计算；一旦手工修改总房费，本次编辑中改日期不会覆盖您输入的金额。续住有不同价格时请直接填写整单新总价。

净收款是本系统登记收款减退款，不等于入住当天的营业收入。平台实际结算到账后，用“平台结算”登记，佣金差额需自行核对；本版本不另算押金、发票、佣金和额外消费。取消订单保留历史金额和收款，需要退款时另外登记。

## 数据和恢复

订单存入 `frontdesk/data/frontdesk.sqlite3`。清理浏览器缓存不会清除账本。系统每次保存前自动生成 SQLite 快照到 `frontdesk/data/backups`，保留最近 100 份；这是同一硬盘上的备份，电脑损坏时仍可能丢失，所以请经常导出 JSON 到外部设备。

正常恢复：设置与备份 → 从备份恢复 → 选择导出的 JSON → 输入“恢复备份”。恢复会替换当前账本，系统先保存恢复前快照。

恢复后所有平台核对状态会重新变为待核对，因为备份时的平台库存不一定与现在相同。

自动 SQLite 快照主要供技术恢复：先关闭服务，完整保留当前 data 文件夹，再从所需快照恢复为新的 data 文件夹中的 `frontdesk.sqlite3`，不要在服务运行时直接覆盖数据库文件。需要时可让维护人员协助。

多个浏览器窗口同时保存时，系统会拒绝旧版本覆盖。遇到提示，关闭编辑弹窗、刷新，再重新填写。联系信息仅建议记录称呼和必要电话，不需要录入身份证。

## 技术验证

在项目文件夹运行：`python -m unittest discover -s frontdesk/tests -v`。

自动验证覆盖跨多晚占房、续住冲突、离店边界、超期在住房量保护、平台分配、精确金额、退款、持久化、备份恢复及并发版本保护。测试用独立临时数据库，不写入酒店正式账本。
